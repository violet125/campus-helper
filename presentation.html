01 / 场景与定位

学生面对的是一项组合任务

“下午有一段空闲时间，想补卡、还书，再找一小时自习，怎么安排？”

用户

在校学生用自然语言描述日期、时段、办理顺序和自习需求。

输出

Agent 调用工具核查条件，生成带时间顺序、地点、材料和来源的计划，说明未安排原因。

原型只使用虚构教学数据，不连接实际校园系统。

说明场景闭环和用户需求。

03 / 工具设计

五个工具覆盖查询与排程

自定义工具

get_current_time
确认上海时区日期和星期。

build_visit_plan
检查开放时间、办理时长、地点间隔和自习条件。

MCP 工具

search_services 查询地点、材料和步骤。

get_service_hours 查询指定日期是否开放。

find_study_spaces 按时段、容量、安静和无障碍条件筛选。

所有校园服务均标注为虚构样例，不能执行预约、支付或挂失。

指认 campus.py 和 mcp_server.py 中的关键代码。

05 / 关键流程

从一句话到一份可下载计划

  1. 读取校园规划 Skill，确认日期、时间和服务顺序
  2. researcher 调用 MCP 查询指南、开放时间和自习空间
  3. build_visit_plan 生成无重叠时间表
  4. critic 检查来源、步行间隔、未安排事项和样例边界
  5. 按模板写入 workspace 中的 Markdown 文件
13:30–14:00 校园卡补办 14:10–14:30 图书馆借还书 14:40–15:40 自习
展示推荐演示话术，并说明时间表来自工具。

07 / 不足

当前原型仍有明确边界

数据限制

  • 校园数据是虚构样例
  • 没有实时教室余位或节假日接口
  • 步行时间是演示假设

工程限制

  • 尚未接入身份认证和多用户隔离
  • 复杂任务仍受模型响应速度影响
  • 工具结果需要人工核对，不能替代官方系统

当前版本适合课程演示，不适合作为真实校园业务系统直接部署。

如实说明不足，避免把原型说成正式系统。

09 / 操作步骤

现场演示路径

操作顺序

  1. 点击“新对话”，确认主区清空
  2. 输入“校园卡补办需要什么材料”
  3. 等待模型调用 Skill 与 MCP 查询
  4. 阅读回答中的材料、地点和时间
  5. 继续输入规划任务并下载 Markdown

演示时只使用虚构样例数据，真实制度以官方文件和现场为准。

这一页用于现场讲解操作。截图展示侧栏能力说明，实际执行过程在后台保存，主区优先展示清晰回答。
